**Client:** Goshen Global Church (300+ member international organisation, multi-country)

The most complete data engineering system I have built. A fully automated, cloud-native analytics platform running in production — not a portfolio exercise.

**What I built**

A multi-source social media and live stream intelligence platform ingesting from YouTube, TikTok, and Facebook, transforming through a dbt medallion architecture, orchestrating daily via Airflow on Cloud Run, and delivering real-time live stream analytics via WebSocket capture.

```
YouTube API v3 + TikTok Live WebSocket + TikTok CSV + Facebook Graph API

      ↓
dbt Staging Layer — 22 models, type casting, deduplication, NULL handling
      ↓
dbt Mart Layer — business logic, cross-platform aggregations, content intelligence
      ↓
dbt Test Suite — 84 automated tests across all models
```

### ⚙️ Crypto Market Analytics Pipeline — Architectural Evolution

**Repos:** `coingecko-analytics-pipeline` · `snowflake_crypto`
**Stack:** `Python` `BigQuery` `Snowflake` `dbt` `Apache Airflow` `Docker` `GitHub Actions`

One pipeline. Two generations. A deliberate engineering decision between each.

**Version 1 — BigQuery + dbt + GitHub Actions**

Fully automated pipeline ingesting live data from 4 external APIs into BigQuery, transforming through dbt staging and mart layers, delivering a 3-page Looker Studio executive dashboard daily at 06:00 UTC.

```
4 APIs (CoinGecko · Fear & Greed · ExchangeRate · Global Market)
→ Python Ingestion → BigQuery Raw → dbt Staging → dbt Marts → Looker Studio
```

| Mart Model | Purpose |
|---|---|
| mart_coin_performance | Market cap rankings, ZAR/EUR pricing, performance categorisation |
| mart_market_sentiment | BTC dominance, momentum signals, sentiment classification |
| mart_fx_crypto_correlation | BTC/ETH dominance vs Fear & Greed index, macro risk signals |

**Two real data quality issues caught during the build**

*Issue 1 caught by dbt tests:* BTC was returning NULL from the exchange rate API on the free tier. The not_null test flagged it immediately. Fixed at ingestion, clean data reloaded, all tests passed.

*Issue 2 caught by visual validation:* FX scorecards were summing rates across 10 mart rows instead of averaging, producing USD/ZAR of 163.9 instead of 16.41. Caught through human eyes on the dashboard output.

> The lesson: dbt tests catch structural issues. Business logic validation requires human eyes on the output. Both layers matter. Neither replaces the other.

**Version 2 — Snowflake + dbt + Airflow + Docker**

Rebuilt after identifying three architectural limitations in Version 1.

| Dimension | Version 1 | Version 2 |
|---|---|---|
| Warehouse | BigQuery | Snowflake |
| Orchestration | GitHub Actions | Apache Airflow |
| Containerisation | None | Docker |
| Incremental models | No | Yes |
| Retry logic | Limited | Native Airflow |
| Environment portability | Manual setup | `docker-compose up` |
